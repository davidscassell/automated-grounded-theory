# Review fixes 0.9.25

`policy_version` is `0.9.25`. Axial coding, selective coding, and theoretical sampling stay experimental. `pattern_min_cases` stays 2. The axial token ceiling stays 24000. `axial_token_budget` stays 6000. Focused `decision_token_budget` stays 6000. `batch_size` stays 1. Tier 4 stays a human `verify`. A metric that was not computed stays null. No live or paid model call was run for this note. The axial planner still builds the full pair space in memory. That limit stays open.

A live LLM-only rerun on 0.9.24, with a TA 1% sample and three Muse documents and both decision budgets at 6000, applied reviews that the package had already marked incomplete. It also scored every open code as a core candidate, kept a withheld row's pattern component eligible, labelled some participant links denied, and reported `unique_pairs` under two different meanings. The quotes below are the shapes of those readings. The fixture is synthetic. It is not study data.

## Decision

Decision: an incomplete focused selection is not applied. `raised_code_ids` stays empty. The ids the validated chunks would have raised are `provisional_raised_code_ids`. `selection_status` is `provisional`, `selection_withheld` is true, `selection_review_applied` is false, and `selection_downstream_eligible` is false. `decision_stop` is the ceiling (`call_allowance`, `token_allowance`, `request_budget`, or `review_error`) or `selection_incomplete`. Codes that were neither reviewed nor omitted are `selection_uncovered_code_ids`. The same rule applies to core selection: `model_core_id` stays empty, `provisional_core_id` holds the merged nomination, `core_status` is `provisional`, `core_downstream_eligible` is false, and `core_uncovered_code_ids` lists the remainder. A complete review still merges and applies. A complete core is downstream eligible only when `model_core_id` is set and the core is not `core_unsupported_by_graph`.

Decision: chunk order does not decide which codes are selectable. Packing still orders focused codes by `code_id`, relationships by `relationship_id`, and core candidates by the evidence score. That order keeps the partition stable. It does not promote a code, because nothing is applied until every item is in a validated chunk, nothing was omitted, and there is no stop. `chunk_order_selects_codes` is false. The report's `uncovered_ids` is the remainder, not a prefix that happened to be packed first.

Decision: when `interrupt` is true and at least one chunk was validated while another planned chunk was not, a withheld focused selection pauses at `selection_pause`. A review that validated nothing, including `max_decision_calls` 0, exports with the stop and does not pause. Resume with `{"continue_selection": true}` to review the uncovered codes, or `{"leave_selection": true}` to export without promoting them. Any other resume value raises `FocusedError`. Continuing clears the ceiling stop and resumes at the unsent chunk. `interrupt` false, a reviewer that was never created, and a plan with no chunks export the withheld result without pausing. LLM mode still resumes an ordinary reviewer checkpoint by itself. This pause is the exception, and the caller's resume value is delivered. The chunk state stays open and provisional until the selection is complete or the caller leaves it. A higher `max_decision_calls` on resume needs `allow_changes`, because that ceiling is procedure. It does not change the chunk hash.

Decision: the chunking fingerprint is `request_budget_v2`, stored as `procedure.decision_review_chunking`. A checkpoint whose value is missing or `request_budget_v1` raises `DecisionChunkingCheckpointError` before `allow_changes` is considered. The plan hash covers the chunking version, kind, per-request budget, ordered ids, chunks, and omissions. It does not cover `max_tokens` or `max_calls`. Those ceilings limit how far a run gets. They do not change which ids share a chunk. The other procedure keys are `incomplete_review_application` (`withhold_incomplete_v1`), `eligibility_rule` (`row_gates_components_v1`), `link_denial_rule` (`affirmative_rejection_v1`), `pattern_quote_rule` (`distinct_endpoint_quotes_v1`), `pair_count_rule` (`space_and_examined_v1`), and `core_candidate_rule` (`focused_categories_v1`). Sampling adds `cost_status_rule` (`configuration_v1`) and locks it the same way it locks `seed` and `source_hash`.

Decision: core candidates are the promoted focused categories. `raised_code_ids` on a complete selection is that set, including an explicit empty list. If `selection_review_complete` is false, `selection_withheld` is true, or `selection_status` is `provisional`, the source is `focused_selection_incomplete` and no candidate is scored. If the source is a focused stage, or it names a `selection_source`, and it has no `raised_code_ids`, the source is `focused_categories_unavailable` and no candidate is scored. There is no silent fallback to every open code. A direct `selective_code` call that carries none of those fields uses `caller_codebook`: the codebook the caller passed. That is the intended set when no focused selection was supplied.

Decision: row eligibility and component eligibility use one rule. A pattern component is `downstream_eligible` and `supports_core` only when the row's `evidence_use` is `supported_evidence`, the pattern is present, and the pattern tier is at least 2. Otherwise both flags are false and `core_support_component` is null. Participant and analyst components stay ineligible. `graph_supported` is false when the row has `downstream_eligible` and it is not true. A rejected "may be related to" row therefore cannot keep a pattern component that still supports a core.

Decision: a single quote that is the evidence for both endpoints does not count as a both-endpoint case. `pattern_min_cases` stays 2, and a case still needs its own quote for each endpoint. The shared quote is dropped from both sides before `both_endpoints` is computed. `shared_quote_for_both_endpoints` records that drop. This is a design choice for this package. It is not a claim that one sentence can never ground two categories. It is the rule that stops one quote from satisfying `pattern_min_cases` 2 by itself.

Decision: denied means the participant affirmatively rejects the from-to link. The negation has to govern the connector: "do not lead", "is not related", "not because", "no relationship", "not what causes", and the same shape. A frequency negation ("not often", "are not often", "not always") is `unvalidated`, polarity stays affirmative, and the qualification is `frequency_negation`. Any other negation that does not reject the link ("is not far", "cannot recall", "is not the schedule") is `unvalidated` with `negation_does_not_reject_link`. Polarity is negative only for a real link rejection. Anything else that is not one clear affirmative link stays unvalidated, hypothetical, or contested, with the qualification that reading already used. The synthetic fixture `tests/fixtures/link_denial_0925.json` has three patterns: a frequency negation, a because-explanation whose negation does not govern the link, and a 721-character affirmative quote with no negation word. Passing the fixture is regression coverage for those three shapes. It is not general semantic accuracy.

Decision: `attrition.unique_pairs` and `pairs_examined_unique` are the same number. It is the count of distinct pairs with a completed examination, which is `len(examined_pairs)` when that list was recorded, and null otherwise. `pair_space_size` is `pair_coverage.pair_count`, otherwise `procedure.planned_pair_count`, otherwise null. Neither field is the materialized plan list. `unique_pairs_explored` remains the completed-examination count used by the planner. A plan list that shrinks between rounds does not change `unique_pairs`.

Decision: reread `cost_status` is `configured` when both `input_usd_per_million` and `output_usd_per_million` are set, and `unset` otherwise. A run with no relevant reread still reports `configured` when the prices are set. A complete expenditure with no sent calls is a known zero dollar amount. Per-relevant dollar amounts stay null when there is no relevant usage to price. A call that did not report usage stays null, not zero.

Decision: 0.9.24 chunk packing is unchanged. One oversized item is still omitted and packing continues. `max_decision_calls` is not raised. `batch_size` stays 1. Claim review packing and saturation review are unchanged. Models still cannot set verified or authorize attribution wording. The axial planner's full pair space stays open.
