## Decisions

Only a validated final core decision sets the core. That replaces the 0.9.34 path that could keep an earlier nomination when the final answer named no core, and the path that could store an id that was not a candidate. `decision` is `select` or `abstain`. Abstain is explicit. An empty `core_id` on a select decision does not become an abstention. An earlier winner is a nomination and is never substituted for the final answer. The rule is `core_final_decision_rule` `final_match_only_v1`.

The core prompt names three different sets: the original eligible candidates, the candidates in this round, and the finalists. A final of two does not say it contains every originally eligible candidate. A later request can quote prior-match rationales, truncated to 240 characters. The rule is `core_prompt_scope_rule` `eligible_round_finalists_v1`. Ordering the bracket by code id is reproducible scheduling. `core_bracket_schedule_note` says that, and `core_bracket_is_substantive_stability` is false. Permuting the input ids does not change the code-id bracket. An alternative bracket can change the chosen core when the chooser is not transitive. That dependence is reported. It is not treated as stability.

An observed conditional pattern stays eligible. That is a policy decision. 0.9.34 blocked every hypothetical-link flag, including a complete retained condition such as `if it rains` on a supported, reviewed pattern. 0.9.35 distinguishes three readings. An observed conditional is a supported pattern under a complete stated condition. It stays eligible, and the condition is carried downstream. A speculative counterfactual stays blocked. An incomplete condition stays blocked. Causal wording below tier 3 stays a separate withhold and does not decide eligibility. The rule is `condition_pattern_rule` `observed_conditional_eligible_v1`. `eligibility_decision_rule` now uses that same value. The fixtures that exercise it are synthetic. This package creates no adjudications.

Each core candidate can carry a compact evidence summary: the category definition, up to two relationship statements, a key variation, and counterevidence. Summaries are on by default (`core_evidence_summaries`). The cap is `core_evidence_token_cap`, default 80 tokens, shrunk so the candidates together stay inside a quarter of the smaller of the per-request budget and the per-step allowance. `core_evidence_extra_tokens_per_candidate` reports the summary size. `core_evidence_improves_selection` stays null. Whether the summaries improve selections is unmeasured. The rule is `core_evidence_summary_rule` `capped_candidate_evidence_v1`.

`one_document_one_respondent` stays off unless the caller sets it.

## What the code does

`ModelCoreDecision` requires `decision` (`select` or `abstain`), `core_id`, and a nonempty `rationale`. Abstain cannot name a core. Select requires a nonempty `core_id`. A validated select whose id is in that match records the winner. Only when that match is the final does the id become `model_core_id`, with `core_status` `applied` and `model_core_decision` `select`. The rationale is the model's rationale. An abstention sets `model_core_id` empty, `core_status` `abstained`, `model_core_decision` `abstain`, `core_selection_withheld` false, `core_downstream_eligible` false, and `core_selection_complete` true, because the tournament finished with an explicit decision not to name a core. An id outside the match is `invalid_decision`, `core_status` `withheld`, and no core, in the opening match and in the final. A payload that fails validation, including an empty select, or a response that does not parse, is `review_error` and leaves `model_core_id` empty even when an earlier match named a winner.

The instruction and `comparison_scope` record `eligible_total`, `eligible_ids`, `round_role`, `match_ids`, `finalists`, `contains_every_eligible_candidate`, and `prior_match_rationales`. The same scope is stored on the bracket round. The planner prices every match as a final that already includes one 240-character prior rationale, so a first-round send is not planned when the later final would not fit.

`classify_condition_pattern` returns `observed_conditional`, `speculative_counterfactual`, `incomplete`, or nothing. Incomplete still blocks `incomplete_condition` and, when the hypothetical flag is set, `hypothetical_link`. Speculative wording stays `hypothetical_link`. An observed conditional does not add `hypothetical_link`. When the row is otherwise eligible, `downstream_condition` and the pattern component carry the condition. `authorizes_tier_3` stays false for a conditional. A sentence that says `lead to` below tier 3 still has `wording_exceeds_tier` and `causal_wording_withheld`.

`candidate_evidence_summary` fits the definition, statements, variation, and counterevidence under the token cap and reports `tokens`, `token_cap`, `truncated`, and `improves_selection` null. Turning summaries off leaves the summary empty and the extra-token count at 0.

The resume fingerprint stays `request_budget_v6`. The new procedure keys are `core_final_decision_rule`, `core_prompt_scope_rule`, `condition_pattern_rule`, and `core_evidence_summary_rule`. `eligibility_decision_rule` changed value. A 0.9.34 checkpoint cannot resume.
