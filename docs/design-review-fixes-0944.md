# 0.9.44 review fixes

Status: current package 0.9.44, built on 0.9.43. This release is reporting and accounting. It does not change evidence exposure, relationship eligibility, reviewer standards, `pattern_min_cases` (2), `one_document_one_respondent` (off), or the 6,000 counterexample cap. No LLM judge is added. Undefined metrics stay null. No Muse or TA data is in this package. Analytic accuracy is unmeasured.

A live axial run on a frozen earlier input was the first live run to follow the 0.9.43 examination order. It selected a core supported by one eligible relationship. When `core_outcome` is `core_selected` and exactly one non-synthetic relationship is `downstream_eligible`, the export sets `core_provisional` and `core_support_note` to: "The core is provisional. It rests on one eligible relationship (rel-1)." The relationship id in that sentence is the id on the row. A selected core with any other eligible count sets `core_provisional` false and leaves the note null. Any other outcome leaves both null. `core_eligible_relationship_count` and `core_eligible_relationship_ids` are always recorded.

## Decisions

1. `call_usage` lists leaf stages: `axial_proposal`, `statement_copy_retry`, `axial_counterexample`, `axial_relation_review`, `axial_saturation_review`, `axial_core_review`, `theoretical_memo`, and `storyline`. A statement-copy retry is its own stage. A schema repair is attributed to the stage whose output it repairs, recorded as `repairs_kind`. A counterexample repair stays on `axial_counterexample`. A repair with no recorded stage stays `schema_repair` and is not forced onto proposals. Omitted, deferred, refused, and not-sent log rows are not calls. The coding subtotal's `usage_completeness` follows its member stages: complete when those members are complete, partial when they differ, and unknown when none of them sent a call. It is not left null.

2. Estimated input, provider input, and provider output are separate fields on each call and each stage. A missing provider count stays null. A stage total is null when any call in that stage lacks that count, so a partial sum is not presented as the total. The overall provider total is null when any leaf stage that sent a call has a null provider total. The overall estimate is the sum of the leaf estimates when every sent call has one. `coding` is the subtotal of proposal, retry, and counterexample calls. It is labeled `subtotal` and is not added again into the overall call or token totals. `reconciles` is true when that subtotal equals its parts and the overall call count equals the leaf sum.

3. The live core report showed 7 calls against a budget of 6. The final assessment is inside the contingent plan: a sole survivor of a non-final round receives one more `final` comparison, and a whole-set match is itself the final comparison. `final_assessment_in_plan` records that. The plan was not missing the call, and the usage report was not counting one call twice. The defect was enforcement. Before each core model call, the run takes the greater of the progress call counter and the `axial_core_review` ledger, and it refuses the call with `core_call_allowance_insufficient` when that figure has already reached `max_core_review_calls`. The model is not called. A contingent shortfall still warns and does not cancel opening matches that fit, because an abstention can shrink the later rounds. Once the allowance is spent, the next call, including the final assessment, is not sent. An allowance of 6 on an 8-candidate bracket that prices at 4 opening calls plus 3 contingent calls sends 6 and does not send `round_role` `final`. An allowance of 7 sends that final call, and the stage ledger equals 7. Resume from the 6-call export with the allowance raised to 7 sends exactly that final call, and the ledger reaches 7. `core_call_accounting.layer` is `enforcement`. `sent_within_allowance` is true when sent calls are within the allowance. Every sent core call consumes the allowance: the prompt-log count, the model-call count, and `calls_used` match.

4. Paradigm roles that arrived as `unspecified` were the schema default, not a dropped value. An omitted `paradigm_role` is stored as `unspecified` with origin `schema_default_unspecified`. An explicit `unspecified` is `model_unspecified`. Any other returned role is `model_returned` and is kept. A reviewer decision with origin `model_returned` replaces the proposal role and sets origin `reviewer`. An explicit reviewer `unspecified` sets origin `reviewer_unspecified`. A reviewer decision that omitted the field does not replace a role the proposal returned. Re-validating a dumped decision keeps that origin, so the omitted field is not reread as an explicit `unspecified`. The package does not invent a role. Consolidation keeps the retained row's role and stores `paradigm_role_records` for every member.

5. An accepted eligible row with an empty `reasons` list is correct. That list withholds rejection reasons. `insufficient_document_count` remains a funnel reason when the recorded document count is below `pattern_min_cases`. Tentative status and thin document support are exported as `evidence_limitations`, not as reasons. `tentative` applies when the tier is missing or below 3, the disposition is `proposed` or `provisional`, or the paradigm role is `unspecified`. `limited_document_support` applies when the document count is missing or below `pattern_min_cases`. Eligibility is unchanged.

6. Unused calls while pairs remain unexamined are reported and the spending rule is unchanged. That choice belongs to a separate policy experiment. `allowance_accounting` records, per stage, `reserved` (the allowance snapshot at the start of axial coding, with relation, saturation, and core refreshed when selective coding starts), `consumed` (leaf calls sent), `released` (calls moved by `allowance_transfers`), and `unused` (`reserved - consumed - released`). Release reasons are kept. The unused note says that an unused call is what remained. It is not evidence that tokens, dollars, or a suitable request were available. An export from before 0.9.44 has no `allowance_reserved` record. Those stages report `reserved` null, with a note that the reserve is unknown. Null is not zero, and consumption against it is not overspending. A recorded zero stays zero.

7. Several assertions can name the same endpoints. `pair_assertions` groups by directed pair (`from_id`, `to_id`) and keeps each assertion's relationship id, statement, evidence, and decision. A different statement is not merged because the endpoints match. The opposite direction is a different group. Identical-statement consolidation before review, from 0.9.42, is unchanged.

8. The selective usage row is an ownership record. Its `calls` count is memo calls plus storyline calls. Core calls are not moved into it. `core_usage_stage` is `axial_core_review` and `referenced_core_calls` is that stage's call count. When memos and the storyline are both disabled, status is `not_requested`. When either was requested and that stage sent no call, status is `incomplete`. Otherwise status is `complete`. The provider token fields on this ownership row stay null so they are not added twice.

Quote-anchoring fixes fold typographic quotes and dashes before the substring check, and they keep `quotes_not_in_cited_passage` with `quote_scope_cause`. Those checks are offline tests. They were not exercised on a live provider run. The export sets `quote_anchoring_live_exercise` false and `quote_anchoring_note` to that limitation.

These checks are engineering and evidence-traceability coverage. Analytic accuracy is unmeasured.
